# Codex — особенности программы

Файл среды: что в этом проекте устроено иначе, когда он открыт в Codex (OpenAI; терминал, VS Code, приложение). Правила проекта — в [AGENTS.md](../../AGENTS.md); здесь только то, чем Codex отличается от других программ. Наблюдения — с датой и версией: поведение программы может измениться.

## Как подключаются правила

Codex читает `AGENTS.md` сам — из каждой папки от корня git до папки, где он открыт (без git — из папки запуска). `CLAUDE.md` Codex не читает: это строка для Claude Code, удалять её не нужно.

- **Лимит.** По умолчанию Codex читает из файлов правил только первые 32 КиБ (`project_doc_max_bytes`), остальное молча отбрасывает. `AGENTS.md` этого проекта больше, поэтому лимит поднимает настройка самого проекта — `.codex/config.toml`; её Codex применяет только в папке, которой выдано доверие. Без доверия — строка `project_doc_max_bytes = 262144` в начале личного файла настроек Codex (`~/.codex/config.toml`, до первой строки в квадратных скобках) и перезапуск. Проверка среды считает размер и говорит человеку, только если правила не помещаются; признак обреза для тебя самого — в самом конце твоих инструкций нет последней строки `AGENTS.md` — курсивной метки о конце файла правил: за задачу не берись.
- **`AGENTS.override.md`** рядом с `AGENTS.md` Codex читает вместо него. Проверка среды говорит об этом человеку.
- **Открыт в подпапке проекта без git** — `AGENTS.md` из корня не найден: попросить открыть Codex в папке проекта.

## Первая настройка

Один раз на проект (проверено на Codex 0.169, 16.11.2026):
1. **Доверить папку** — Codex спрашивает при первом открытии: «Trust and continue», не «Open restricted». Без доверия не работают настройки проекта (лимит, стиль) и его проверки.
2. **Одобрить проверки проекта** — набрать `/hooks` и одобрить проверки этого проекта.
3. **Перезапустить Codex** — до перезапуска он читает прежние настройки.

Нужен Python 3 — `python3`, `python` или `py`. Проект без git работает (проверено там же).

## Настройки и проверки проекта

- **Файлы настроек:** `.codex/hooks.json` — проверки проекта; `.codex/config.toml` — лимит и стиль ответов; `.codex/agents/` — роли субагентов (проверяющий `reviewer`). Личные — `~/.codex/config.toml` (или папка из `CODEX_HOME`).
- **Проверки проекта** — записи в `.codex/hooks.json`: `SessionStart` → `hooks/start.py`; `UserPromptSubmit` → `hooks/consent.py`; `PreToolUse` (`Bash|apply_patch`) → `hooks/raw_guard.py`; `Stop` → `hooks/judge.py`. Команда (`command` — Mac и Linux, `commandWindows` — Windows, PowerShell) находит корень проекта по `.codex/hooks.json` и запускает скрипт первым найденным Python; сбой работе не мешает.
- **Выключить все проверки разом** — отклонить их в `/hooks` (отдельного выключателя проекта в настройках Codex мы не проверяли).
- **Одобрение — по содержимому записей.** Изменилась команда записи в `.codex/hooks.json` для системы человека — `command` на Mac и Linux, `commandWindows` на Windows (после обновления проекта или правки) — одобрение снято, проверки молча не запускаются, пока человек не одобрит их заново в `/hooks`. Правка самих скриптов `hooks/` одобрения не снимает; изменённые записи журнал называет в «Как принять».
- **Страж `raw/`** видит правки через `apply_patch` и команды шелла; команды проверяет по шаблонам. Ввод в уже запущенную программу (`write_stdin`) он не видит — проверено 16.11.2026 на Codex 0.169: запись в `raw/` из запущенного интерпретатора прошла; инструменты подключённых серверов — тоже. Поэтому правило «`raw/` неизменяем» главнее стража: в `raw/` не пиши ни одним путём. Отказ стража не обходить и не просить разрешить это в окне Codex.

## Стиль ответов

Текст стиля — ключ `developer_instructions` в `.codex/config.toml` (тот же текст, что в `.claude/output-styles/plain.md` и `.qwen/output-styles/plain.md`). Codex применяет его, когда папке выдано доверие, — тогда в твоих инструкциях есть раздел «Стиль ответов: сообщение из двух частей». Раздела нет — читай текст этого ключа в начале чата и после сжатия контекста и следуй ему. Варианта «только для вас» у Codex нет: личный файл настроек `~/.codex/config.toml` общий для всех проектов человека — на вопрос «для всей команды или только для вас» сказать это и предложить выбор «для всей команды» или «не ставить».

## Субагенты без истории разговора

Инструмент `spawn_agent` — **строго с `fork_turns="none"`**: по умолчанию дочерний агент получает весь разговор, и проверка выглядит независимой, не будучи ею; всё нужное ему — в тексте задания. Готовый проверяющий — агент `reviewer` из `.codex/agents/`. Песочница субагента наследует права основного разговора (проверено 26.10.2026: `sandbox_mode = "read-only"` в файле агента не применился) — в задании проверяющему прямо пиши «ничего не создавай и не меняй». Одновременно Codex держит ограниченное число агентов — запускай проверяющих волнами: предел — не отказ механизма.

## Коммиты

Песочница Codex не даёт писать в `.git/` (проверено на 0.164): коммит после ingest или профилактики требует одобрения в окне — попросить; отказ — коммит пропустить и сказать человеку, что изменения не сохранены в истории.

## Запуск без окна

`codex exec` — безоконный запуск: человека в разговоре нет, вопросов не задавать.

## Сеть при обновлении

Песочница Codex обычно без сети (команда падает с `Could not resolve host`) — это не отказ человека: повтори те же команды проверки обновлений, попросив у человека разрешение на сеть в окне Codex — только на эти команды, не насовсем. Не разрешил — проверка не выполнена; человеку действие: «разреши Codex сеть для этой проверки в окне одобрения или открой проект в Codex с доступом в сеть — там обновление пройдёт». Встроенный веб-поиск Codex для этой проверки запрещён.

## Оценщик ответа и его цена

`hooks/judge.py` после части ответов запускает отдельный короткий `codex exec` (без сохранения разговора, без личных настроек, только чтение, низкий уровень рассуждения) — около 10 секунд (измерено 16.11.2026: 8,7 с). При входе в Codex по ключу API каждый такой запуск тратит деньги; при входе по подписке — расходует её лимиты. Нет команды `codex` там, где её ищут проверки, — проверка среды скажет человеку.

## Встроенная память программы

Память Codex (`memories = true` в разделе `[features]` личных настроек) — личный кэш, мимо памяти проекта и не виден в других программах: знание проекта — только в `wiki/` через ingest. Проверка среды говорит человеку, если память включена.

## Удаление, когда программа не даёт

Общий порядок — [lint.md](../lint.md), «Удаление, когда среда не даёт»; здесь — как просить в Codex. Песочница закрывает стирание и запись вне разрешённых путей, пока человек не одобрит их в окне (в `.codex/` и `.git/` песочница писать не даёт — проверено на Codex 0.164, 26.10.2026; окна одобрения запуском не проверены — описание по документации Codex).

- **Запрос:** одна попытка через окно одобрения — повторить ту же команду так, чтобы Codex спросил человека; причину — одной фразой в чате перед вызовом.
- **Отказ человека в окне** — п. 4 общего порядка (оставить или сложить в `_to_delete`), заново не просить.
- **Режим, где Codex не спрашивает и запрещает** (только чтение) — отдельным коротким сообщением: «Удалить не дал Codex. Смени режим разрешений на тот, где Codex спрашивает перед изменениями, и напиши „удали“». Ответил, что сменил, — повторить один раз.

## Запись настроек, когда программа не даёт

Общий порядок — [lint.md](../lint.md), «Запись проверок и настроек программ»; здесь — Codex.

- Запись в `.codex/` песочница без одобрения не даёт — это не отказ человека: попросить разрешить её в окне Codex.
- Что нужно от человека в вопросе (п. 2 общего порядка): разрешить запись в окне, сменить режим разрешений, доверить папку или одобрить проверки в `/hooks` — назвать нужное.
- **После записи `.codex/hooks.json`** — если изменилась команда для системы человека, попросить одобрить проверки заново (`/hooks`) и перезапустить Codex (п. 6 общего порядка).
- Цену проверки после ответа в описании для человека называть: «при входе по ключу API это тратит деньги».
