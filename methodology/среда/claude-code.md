# Claude Code — особенности программы

Файл среды: что в этом проекте устроено иначе, когда он открыт в Claude Code (терминал, VS Code, JetBrains) или в Claude Desktop. Правила проекта — в [AGENTS.md](../../AGENTS.md); здесь только то, чем Claude Code отличается от других программ. Наблюдения — с датой и версией: поведение программы может измениться.

## Как подключаются правила

Claude Code читает `CLAUDE.md`, а не `AGENTS.md`: `AGENTS.md` сам по себе он загружает только при функции, которую включает или выключает сервер Anthropic (проверено 16.11.2026 запуском с выключенными инструментами чтения на Claude Code 2.1.325 и 2.1.83: без `CLAUDE.md` правила не загрузились). Поэтому в корне лежит `CLAUDE.md` из одной строки `@AGENTS.md` — штатный импорт Claude Code: правила загружаются целиком из `AGENTS.md`. Удалять его не нужно, в других программах он не используется. `CLAUDE.local.md` и `CLAUDE.md` в папках выше проекта не мешают (проверено там же).

`CLAUDE.md` нет или в нём другое — проверка среды при старте говорит об этом человеку; починка — вернуть файл ровно с этой строкой. Правила человека в `CLAUDE.md` не пишутся: место для них — `AGENTS.md`.

## Первая настройка

В Claude Code — ничего: проверки проекта (`hooks/`) запускаются сами по записям в `.claude/settings.json` (проверено на 2.1.325). Нужен `python3`. В Claude Desktop — строка для поля инструкций проекта (её текст — раздел «Claude Desktop» ниже).

## Настройки и проверки проекта

- **Файлы настроек:** `.claude/settings.json` — общий, в проекте (проверки и стиль ответов); личные — `.claude/settings.local.json` (только на этом компьютере, не в коммит) и `~/.claude/settings.json`.
- **Проверки проекта** — записи в `.claude/settings.json`: `SessionStart` (с `matcher` `startup|resume|clear|compact` — и после сжатия контекста) → `hooks/start.py`; `UserPromptSubmit` → `hooks/consent.py`; `PreToolUse` (`Write|Edit|MultiEdit|NotebookEdit|Bash|Monitor`) → `hooks/raw_guard.py`; `Stop` → `hooks/judge.py`. Команда — `python3 "$CLAUDE_PROJECT_DIR/hooks/<скрипт>.py" --program claude`, с проверкой `python3` впереди и `|| true` в конце.
- **Одобрять не нужно:** Claude Code запускает проверки проекта без окна одобрения.
- **Выключены все разом** — ключ `disableAllHooks: true` в любом из файлов настроек. Флаг — выбор человека: не трогать, назвать.
- **Страж `raw/`** видит правки файлов и команды шелла; команды проверяет по шаблонам — поэтому правило «`raw/` неизменяем» главнее стража.

## Стиль ответов

Ключ `"outputStyle": "plain"` в `.claude/settings.json` (или в личном `settings.local.json`) и файл `.claude/output-styles/plain.md`. Включён — в твоих инструкциях есть раздел «Стиль ответов: сообщение из двух частей». Файл стиля для чтения вручную — `.claude/output-styles/plain.md`. В Claude Desktop стилей ответов проекта нет — читай файл стиля всегда, кроме строк журнала «не ставим» и «ждёт ответа».

## Субагенты без истории разговора

Новый субагент инструмента запуска агентов (обычный тип, не `fork`) начинает без истории разговора — такой и нужен для независимой проверки: всё нужное ему — в тексте задания. Тип `fork` получает весь разговор и независимым не будет.

## Запуск без окна

`claude -p` — безоконный запуск: человека в разговоре нет, вопросов не задавать.

## Сеть при обновлении

Шелл обычно с сетью. Песочница без сети — шаг 1 проверки обновлений сделать инструментом чтения страниц `WebFetch` (живой GET, идёт мимо песочницы); `WebSearch` для неё запрещён. Шагам 2–8 нужен `git` с сетью — попросить разрешить эту команду вне песочницы в окне Claude Code; не разрешил — человеку: «открой проект в Claude Code без песочницы — там обновление пройдёт». В Claude Desktop без шелла с сетью — шаг 1 через `WebFetch`, а человеку: «открой проект во вкладке Code или в Claude Code — там обновление пройдёт».

## Оценщик ответа и его цена

`hooks/judge.py` спрашивает модель Haiku тем же Claude Code (`claude -p --model haiku`, без сохранения разговора и без проверок проекта), на несколько секунд после части ответов. Расходует ту же подписку или ключ, что и основной разговор.

## Встроенная память программы

Авто-память Claude Code (`MEMORY.md`, папка `memory/`) — личный кэш между разговорами, не память проекта: знание проекта — только в `wiki/` через ingest.

## Claude Desktop

- **Правила.** Папка разговора Claude Desktop (Cowork) лежит вне проекта: ни `CLAUDE.md`, ни проверки проекта там не загружаются. Правила держит строка в поле инструкций проекта (**Project settings → Memory → Project instructions**; папка проекта — в **Environment → Pre-approved folders**): «Перед первым ответом в каждом чате прочитай AGENTS.md из папки проекта и следуй ему; не можешь открыть файл — скажи об этом. Записывай в файлы этой папки, не в память приложения (MEMORY.md).» В проектах до 3.0.0 строка называла `CLAUDE.md` — после перехода её нужно заменить: `CLAUDE.md` теперь только ссылка, и прочитанный как файл он правил не даёт.
- **Проверки проекта не работают** — правила держатся текстом. Проверки ставить не нужно: одной строкой сказать человеку, что они заработают, когда проект откроют в Claude Code; строку журнала о проверках не писать — она общая для всех программ и заглушила бы их там.

## Удаление, когда программа не даёт

Общий порядок — [lint.md](../lint.md), «Удаление, когда среда не даёт»; здесь — как просить в Claude Code.

- **Терминал, VS Code, JetBrains** — удаление подтверждает сама программа в своём окне разрешений; отдельного запроса нет.
- **Проект в Claude Desktop (не вкладка Code)** — стирание в подключённой папке закрыто, пока человек не разрешит. Не уверен, где работаешь, — считай, что в Claude Desktop: команду для терминала человеку не давать. Удаление не прошло («Operation not permitted») — запросить разрешение инструментом среды, **одним вызовом**: облачная сессия (`device_request_delete_permission`) — на подключённую папку, где лежит проект, с причиной для окна; локальная (`allow_cowork_file_delete`) — на путь любого одобренного файла, причину окно не покажет — сказать её в чате перед вызовом. Подключённая папка шире проекта (например, все «Документы») — сказать, что разрешение откроет её целиком, и вместо запроса задать вопрос п. 4 общего порядка. Инструмента разрешения среди доступных нет (и поиск инструментов его не нашёл) — сразу вопрос п. 4: инструкция среды велит в этом случае молча складывать файлы в `_to_delete/`, здесь — сперва спросить. Разрешение открывает удаление во всей подключённой папке до конца чата (наблюдение 10.09.2026).
- **Отказ автоматического режима** (в ответе есть «auto mode classifier») — отдельным коротким сообщением, им закончить ход: «Удалить не дал автоматический режим. Переключи режим у поля ввода (в терминале — Shift+Tab) на тот, где я спрашиваю разрешения (в Claude Desktop он называется „Manual“; писать это в чат не нужно), и напиши „удали“ — появится окно, разреши. Потом режим можно вернуть». Человек ответил, что переключил («удали», «готово», «Manual» и т. п.), — запросить снова; отказ повторился — к п. 4 общего порядка.

## Запись настроек, когда программа не даёт

Общий порядок — [lint.md](../lint.md), «Запись проверок и настроек программ»; здесь — автоматический режим разрешений Claude Code. Только в основном разговоре: делегированный субагент ответа человека не получает — там не устанавливать.

В автоматическом режиме разрешений Claude Code может отклонить запись в `.claude/`, **не показав окна человеку**, — даже если человек заранее согласился на обновление: согласие на задачу эту проверку не проходит, нужен его ответ **после** отказа (наблюдение 11.09.2026, Claude Code 2.1.263–268). Отказы копятся: после нескольких подряд программа прерывает работу или сама показывает окно, которое закрывается без ответа.

- **Вопрос после отказа** (п. 2 общего порядка), образец:
  > Отдельный вопрос про настройки проекта. Защита автоматического режима не дала мне вписать две автоматические проверки из обновления — похоже, приняла это за то, что я меняю себе правила работы без твоего ведома. Правила и правда меняются: первая перед каждым моим ходом добавляет мне напоминание спрашивать тебя, прежде чем что-то сохранять; вторая иногда после моего ответа отдаёт его вместе с твоей последней репликой отдельной быстрой модели, и та может вернуть меня дописать одну строку — в такие ходы ответ приходит на несколько секунд позже. Ставим — ответь «впиши проверки»; не ставим — «не ставь».
- **После «впиши проверки»** защита может пропустить запись; пропустит ли она стиль ответов, запуском не проверено: не пропустила — сразу следующий пункт.
- **Отказ повторился** (п. 4 общего порядка) — отдельным сообщением: «Защита снова не пропустила. Переключи режим у поля ввода (в терминале — Shift+Tab) с автоматического на тот, где я спрашиваю разрешения перед правкой файлов — название в чат писать не нужно — и напиши „впиши проверки“. Появится окно с точной правкой: разреши. Потом верни режим обратно.»
- **Одобрять проверки после записи** в Claude Code не нужно (п. 6 общего порядка не применяется).
