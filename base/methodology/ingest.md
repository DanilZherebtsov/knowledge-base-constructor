# Ingest — добавление нового знания

Запускается фразами: «обработай этот документ», «запомни это», «зафиксируй», «добавь в вики».

Когда человек кидает файлы в `input/` (свалка для входящих), указывает на источник или кладёт файл в `raw/`:

1. **Прочитать источник.** Длинный (многостраничный материал, длинная расшифровка) — читать по частям, не пробегать. Сначала обсудить ключевые выводы и подтвердить намерение перед изменением вики.
2. **Распознать вход и разместить — раскладка это задача Claude, не человека.** Прежде чем раскладывать, распознай: это **рабочий исходный код** (дерево кода, деплоимый сайт, скрипты, проект со сборкой/манифестом) или **обычный материал** (документ, расшифровка, данные, чужой код-пример для изучения)?
   - **Рабочий код** — НЕ закапывать в `raw/`. Спросить человека простыми словами: «это код, который будешь здесь вести и развивать, или чужой пример для изучения?». Если **ведём / меняем / деплоим** → код живёт в **корневой папке, названной по сути** (`landing/`, `src/`, `scripts/`), создаётся по решению человека; **не** `raw/` и **не** `output/`. Файлы на диске — источник правды; в вику идёт только знание о нём (что это, ключевые факты — оффер, цены, операционка), сам код — нет. **Код приехал готовым — знания о нём в вике ещё нет:** до первой задачи по нему предложи разведочный проход (описать модули и контракты в вику, по странице на модуль), иначе проверка постановки будет читать пустоту и молча вернёт «чисто». <<СЛОТ OWNED-CODE: при активной механике `software-engineering` — заменить на: «раскладку код-папки, конвенции владения кодом, цикл исполнения и предложение ролей ведёт [software-engineering.md](software-engineering.md)». В чистом base без механики — оставить: «если проект всерьёз начинает владеть кодом, предложи человеку подключить механику `software-engineering`».>> Если человек говорит «это пример для изучения» — дальше как обычный материал.
   - **Входящий фирменный стиль** (логотип, брендбук, гайдлайны, макеты, готовая дека, фирменные шрифты) — не закапывать в `raw/` молча. Спросить простыми словами: **«это наш стиль, по которому дальше делаем всё, — или чужой пример для насмотренности?»**. «Наш» → значения переносятся в `BRAND.md` (корневой файл, правит человек), файл-источник кладётся рядом и остаётся источником правды; в вику идёт только факт и решение, не пересказ гайдлайнов. «Пример» → это референс без обязательств, дальше как обычный материал. <<СЛОТ OWNED-DESIGN: при активной механике `design` — заменить на: «разбор входящего фирстиля, его перенос в `BRAND.md` и дальнейшую работу с видимым ведёт [design.md](design.md)». В чистом base без механики — оставить: «если проект начинает всерьёз производить видимое, предложи подключить механику `design`».>>
   - **Обычный материал** — источник из `input/` (или указанный) переместить в подходящую подпапку `raw/<концерн>/YYYY-MM-DD-slug.md`; нет подходящей — завести новую и вписать в дерево `CLAUDE.md` (правило «Структура растёт по мере надобности»). Человеку подпапки `raw/` знать не нужно — он кидает в `input/`. Сохранить оригинал. **Удалить секреты** (пароли, ключи, лишние перс.данные). Добавить метаданный заголовок: источник (URL, если есть), дата получения, дата публикации/документа (если известна), авторы. После размещения `input/` пустеет (файлы перемещены в `raw/`).
3. **Скомпилировать в вики.** Единица знания — <<СЛОТ KNOWLEDGE-UNIT: страница (по умолчанию) | `claim` для research>>. Для каждой затронутой единицы:
   - **Тот же тезис** → объединить, добавить источник в `sources:`, обновить точечно.
   - **Новая концепция** → новая страница в подходящей type-папке, имя по концепции (не по имени файла). Для типов с префиксной группировкой — использовать префикс. Выбор типа и формат — [page-conventions.md](page-conventions.md).
   - **Противоречие** → аннотировать конфликт в тексте, обозначить обе стороны, вынести на разрешение человеком. Не выбирать молча.
   - **Идёт работа в роли** (открыт `roles/<роль>.md`) → страница получает метку среза роли: префикс имени у новой страницы, тег роли в `tags:` — и у новой, и у той, куда дописали (нет тега → добавить). Без метки находка выпадает из среза роли навсегда: разметка при создании роли разовая, а записи идут потоком. Механика — [roles.md](roles.md).
4. **Каскад.** Просканировать ту же type-папку и индекс на материально затронутые страницы. Обновить, освежить `updated:`.
5. **Обновить `wiki/index.md`** — записи затронутых страниц. Формат — [index-log-format.md](index-log-format.md).
6. **Дописать в `wiki/log.md`:**
   ```
   ## [YYYY-MM-DD] ingest | <название основной страницы>
   - Updated: <каскадно-обновлённая страница>
   ```
7. **Закоммитить — если проект под git.** Один коммит, сообщение `ingest: <источник>`. Без git — шаг пропускается (история в `log.md` и датах страниц).

Важное правило: **при обновлении любого утверждения — перечитайте сырой источник, на который оно ссылается.** Не относитесь к тексту вики как к первоисточнику — так заводится дрейф.

**Большой источник** (час+ интервью, подробный отчёт): не извлекать всё за один проход — за ingest 3–5 ключевых пунктов, остальное пометить прямо в raw-файле («мин. 45:00: про X — к рассмотрению») и вернуться позже.
