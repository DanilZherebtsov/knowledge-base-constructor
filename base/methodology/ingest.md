# Ingest — добавление нового знания

Запускается фразами: «обработай этот документ», «запомни это», «зафиксируй», «добавь в вики». Знание не из файла, а из самого разговора — раздел «Знание из разговора» ниже.

Когда человек кидает файлы в `input/` (свалка для входящих), указывает на источник или кладёт файл в `raw/`:

1. **Прочитать источник.** Длинный (многостраничный материал, длинная расшифровка) — читать по частям, не пробегать. Сначала обсудить ключевые выводы и подтвердить намерение перед изменением вики.
2. **Распознать вход и разместить — раскладка это задача Claude, не человека.** Прежде чем раскладывать, распознай: это **рабочий исходный код** (дерево кода, деплоимый сайт, скрипты, проект со сборкой/манифестом) или **обычный материал** (документ, расшифровка, данные, чужой код-пример для изучения)?
   - **Рабочий код** — НЕ закапывать в `raw/`. Спросить человека простыми словами: «это код, который будешь здесь вести и развивать, или чужой пример для изучения?». Если **ведём / меняем / деплоим** → код живёт в **корневой папке, названной по сути** (`landing/`, `src/`, `scripts/`), создаётся по решению человека; **не** `raw/` и **не** `output/`. Файлы на диске — источник правды; в вику идёт только знание о нём (что это, ключевые факты — оффер, цены, операционка), сам код — нет. **Код приехал готовым — знания о нём в вике ещё нет:** до первой задачи по нему предложи разведочный проход (описать модули и контракты в вику, по странице на модуль), иначе проверка постановки будет читать пустоту и молча вернёт «чисто». <<СЛОТ OWNED-CODE: при активной механике `software-engineering` — заменить на: «раскладку код-папки, конвенции владения кодом, цикл исполнения и предложение ролей ведёт [software-engineering.md](software-engineering.md)». В чистом base без механики — оставить: «если проект всерьёз начинает владеть кодом, предложи человеку подключить механику `software-engineering`; порядок подключения — [lint.md](lint.md), «Подключить способность, которой в проекте нет»».>> Если человек говорит «это пример для изучения» — дальше как обычный материал.
   - **Входящий фирменный стиль** (логотип, брендбук, гайдлайны, макеты, готовая дека, фирменные шрифты) — не закапывать в `raw/` молча. Спросить простыми словами: **«это наш стиль, по которому дальше делаем всё, — или чужой пример для насмотренности?»**. «Наш» → значения переносятся в `BRAND.md` (корневой файл, правит человек), файл-источник кладётся рядом и остаётся источником правды; в вику идёт только факт и решение, не пересказ гайдлайнов. «Пример» → это референс без обязательств, дальше как обычный материал. <<СЛОТ OWNED-DESIGN: при активной механике `design` — заменить на: «разбор входящего фирстиля, его перенос в `BRAND.md` и дальнейшую работу с видимым ведёт [design.md](design.md)». В чистом base без механики — оставить: «если проект начинает всерьёз производить видимое, предложи подключить механику `design`; порядок подключения — [lint.md](lint.md), «Подключить способность, которой в проекте нет»».>>
   - **Обычный материал** — источник из `input/` (или указанный) переместить в подходящую подпапку `raw/<концерн>/YYYY-MM-DD-slug.md`; нет подходящей — завести новую и вписать в дерево `CLAUDE.md` (правило «Структура растёт по мере надобности»). Подпапки `raw/` заранее не заводятся: они появляются здесь, по факту прихода материала. Имя новой брать из словаря класса, если материал в него ложится, — так раскладка остаётся однородной: <<СЛОТ RAW-DEFAULTS: словарь имён подпапок `raw/` класса; дефолт — по концерну материала, catch-all `прочее/`>>. Человеку подпапки `raw/` знать не нужно — он кидает в `input/`. Сохранить оригинал. **Удалить секреты** (пароли, ключи, лишние перс.данные). Добавить метаданный заголовок: источник (URL, если есть), дата получения, дата публикации/документа (если известна), авторы. После размещения `input/` пустеет (файлы перемещены в `raw/`).
3. **Скомпилировать в вики.** Единица знания — <<СЛОТ KNOWLEDGE-UNIT: страница (по умолчанию) | `claim` для research>>. Для каждой затронутой единицы:
   - **Тот же тезис** → объединить, добавить источник в `sources:`, обновить точечно. Утверждение было помечено `[со слов, документом не подтверждено]` или `[вывод Claude, не проверен]`, а новый источник его подтверждает — метку снять.
   - **Новая концепция** → новая страница в подходящей type-папке, имя по концепции (не по имени файла). Для типов с префиксной группировкой — использовать префикс. Выбор типа и формат — [page-conventions.md](page-conventions.md).
   - **Противоречие** → аннотировать конфликт в тексте, обозначить обе стороны, вынести на разрешение человеком. Не выбирать молча.
   - **Идёт работа в роли** (открыт `roles/<роль>.md`) → страница получает метку среза роли: префикс имени у новой страницы, тег роли в `tags:` — и у новой, и у той, куда дописали (нет тега → добавить). Без метки находка выпадает из среза роли навсегда: разметка при создании роли разовая, а записи идут потоком. Механика — [roles.md](roles.md).
4. **Каскад.** Просканировать ту же type-папку и индекс на материально затронутые страницы. Обновить, освежить `updated:`.
5. **Обновить `wiki/index.md`** — записи затронутых страниц. Формат — [index-log-format.md](index-log-format.md).
6. **Дописать в `wiki/log.md`:**
   ```
   ## [YYYY-MM-DD] ingest | <название основной страницы>
   - Updated: <каскадно-обновлённая страница>
   ```
7. **Закоммитить — если проект под git.** Один коммит, сообщение `ingest: <источник>`. Без git — шаг пропускается (история в `log.md` и датах страниц).

Важное правило: **при обновлении любого утверждения — перечитайте сырой источник, на который оно ссылается.** Не относитесь к тексту вики как к первоисточнику — так заводится дрейф.

**Большой источник** (час+ интервью, подробный отчёт): не извлекать всё за один проход — за ingest 3–5 ключевых пунктов, остальное пометить прямо в raw-файле («мин. 45:00: про X — к рассмотрению») и вернуться позже.

## Знание из разговора (без документа)

Вход — не файл, а то, что выяснилось в разговоре: по правилу «Просьба решена» в `CLAUDE.md` или по прямому «запомни это». Строка-предложение и «да, запиши» — это и есть сверка понимания; прямая просьба записать («запомни это», «запиши в память») — уже согласие (кроме персональных данных третьих лиц); рассказ человека о том, что он сам записывает или диктует, — нет. Одна-две находки — изолированная дописка: сверка понимания — сама строка-предложение и «да», независимая проверка не включается; ADR и расхождение с вики — по обычной мерке риска. `sources:` обязателен и здесь. Порядок:

1. **Подтверждение человека — до любой записи**, включая `raw/`: там ничего не удаляется. Персональные данные третьих лиц (телефоны, адреса) — только если человек сказал «да» именно на них.
2. **Заметка — одна на разговор:** `raw/из-чата/YYYY-MM-DD-<тема>.md` — единственный файл `raw/` со словами нашего чата. Не путать с расшифровками встреч (у класса своя папка): там чужая речь целиком, здесь выписка из нашего чата. Подпапку завести при первой записи и вписать в дерево `CLAUDE.md`. Шапка — дата первой записи, кто участвовал, о чём шёл разговор. Каждая находка — пунктом `## N. <кратко>`; следующая подтверждённая в том же разговоре — новым пунктом в конец, записанное не правится (поправка — новым пунктом со ссылкой на старый). В пункте:
   - **слова человека** (его решение, поправка, факт, который знает он) — **дословно**, из текущего разговора; после сжатия контекста их нет — пометить «пересказ» или попросить повторить, сочинять цитату нельзя;
   - **вывод самого Claude** (найденная им причина, прочитанный им формат) — только со снимком доказательства (вывод команды, кусок файла); без снимка — пометкой `[вывод Claude, не проверен]` и в заметке, и на странице;
   - **непостоянное** (вывод команды, ответ сервиса, страница сайта, файл из `output/`) — снимок нужного куска: через месяц его не перечитать. Прямой ссылкой — только файлы `raw/` и файлы кода с коммитом (`путь@<коммит>`; без git — снимком).

   **Секрет — не находка** ([secrets-rules.md](secrets-rules.md)): в заметку идёт только имя переменной и где она лежит; значение появлялось в чате — сказать, что доступ засвечен, и предложить сменить. Выводы команд до записи проверить на токены и строки подключения.
3. **Дальше — как для обычного материала: от «Скомпилировать в вики» до «Закоммитить» включительно.** Источник — `[raw/из-чата/<файл>.md, п. N]`, у принципа поле «Источник» — туда же. Факт о мире со слов человека, не сверенный с документом, — строкой `[со слов, документом не подтверждено]` сразу после утверждения (его решение и поправка — не факты о мире, метка не нужна). Коммит — `ingest: разговор YYYY-MM-DD — <тема>, п. N`, файлы — по путям (`wiki/`, `raw/из-чата/`), не всё подряд.
