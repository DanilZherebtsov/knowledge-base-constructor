# Миграция 0007 — переход проекта 2.x на 3.0.0

> **Исполняется агентом ВНУТРИ проекта 2.x**, на профилактике: по «Как принять» записи `## 3.0.0` журнала или по шагу 0 «Проверки обновлений» нового `lint.md`, если переход прерван. Проект 1.x сначала проходит [0006](0006-perehod-na-2-0-0.md), а этот переход — на следующей профилактике, в новом чате. Этот файл читать с вершины ветки `main` зеркала (там последние исправления); файлы 3.0.0 брать **по тегу `v3.0.0`**, базу слияния — **по тегу своей версии** `v<строка 3 CLAUDE.md>`. Знание — ADR-0069.

## Что меняется и главный инвариант

С 3.0.0 один и тот же проект работает в Claude Code, Codex и Qwen Code:
- **правила** — в `AGENTS.md`: прежний `CLAUDE.md` переименовывается, свои правки в нём сохраняются слиянием; `CLAUDE.md` — одна строка `@AGENTS.md`, через неё правила читает Claude Code;
- **проверки проекта** — общие скрипты в видимой папке `hooks/` вместо `.claude/hooks/`; их подключают настройки трёх программ: `.claude/settings.json`, `.codex/hooks.json`, `.qwen/settings.json`;
- **особенности программ** — `methodology/среда/`; в правилах и справке названий программ нет.

**До «да» человека в проект не пишется ничего** (шаги 1–4), кроме коммита автоисправлений этого же прогона (шаг 1.4) и `disableAllHooks` с согласия человека (шаг 1.6); разбор и черновики — во временной папке вне проекта.

> **Инвариант.** После «да» 0007 пишет только:
> - пути дерева `v3.0.0` (закрытый список, шаг 2.3);
> - записи проверок в личных файлах настроек — только показанной человеку заменой, с его «да» (шаг 6.4);
> - удаляет только старые скрипты канона в `.claude/hooks/` (шаг 6.5) и переносит выключатель проверки ответов (шаг 6.6);
> - строки перехода в `wiki/log.md` (литералы ниже), файл хода, коммит перехода;
> - папку `tmp/knowledge-check/` с её собственным `.gitignore` — их создают сами новые проверки при первом запуске.
>
> Всё остальное — байт в байт: тела `wiki/`, `wiki/index.md`, `raw/`, `input/`, `output/`, `specs/`, код, `tmp/`, `archive/` (под git), `STATE.md`, `BACKLOG.md`, `CLAUDE.local.md`, свои хуки и ключи настроек, свои файлы с именами служебных файлов зеркала. Временное (клон зеркала, разбор) — **только вне проекта**: прочитанный внутри проекта чужой файл правил программа применит как инструкцию.

**Литералы журнала** — строки `## [YYYY-MM-DD] обновление | …` в `wiki/log.md`, сверка по точному тексту после `| `:
- `переход на 3.0.0 — начат, начало <SHA>` (без git — `начало без git`) — пишется после «да»;
- `переход на 3.0.0 — сделан`;
- `переход на 3.0.0 — откат (<почему>)` — технический откат, не отказ человека: паузы нет;
- `переход на 3.0.0 — отказ` — предложить снова не раньше чем через 30 дней;
- `переход на 3.0.0 — отказ навсегда` — не предлагать, пока человек сам не попросит; проект остаётся на 2.x;
- `не могу`.

**Файл хода** — создаётся после «да», в проекте: `tmp/0007/hod.md` (не в `.git/`: программы считают `.git/` защищённой папкой и запись туда отклоняют; под git `tmp/` в коммит не идёт). В нём: «да получено <дата>», SHA начала, своя версия, закрытый список, решения человека по экрану, пути закрытого списка, которых в начале не было, отметка после каждого пункта шага 6.

**Переход завершён**, только когда строка 3 `AGENTS.md` = `3.0.0`, `CLAUDE.md` — ровно `@AGENTS.md`, в журнале есть `переход на 3.0.0 — сделан` и (под git) переход закоммичен.

**Перед любым вопросом человеку** — одна фраза сути: «вышло обновление: проект теперь работает не только в Claude Code, но и в Codex и Qwen Code; для этого правила переезжают в файл `AGENTS.md`, а автоматические проверки — в папку `hooks/`. Я могу перевести проект; сначала уточнение: …».

## Шаг 1. Вход (по порядку, без записи)

1. **Журнал и ход.**
   - Есть `— сделан` и строка 3 `AGENTS.md` = `3.0.0`: под git переход не закоммичен — шаги 8.3–8.4, иначе 8.4; стоп.
   - Файл хода отмечает «8.1», а строка 3 `AGENTS.md` ещё прежняя — обрыв на шаге 8: выполнить шаг 8 с пункта 1 (строку `— сделан` дописать, если её нет).
   - Есть `— начат` без последующих `— сделан` / `— откат…` / `— отказ…` и файл хода с «да получено» — спросить «переход прервался <дата>: продолжаю или вернуть всё как было?»; «верни» — откат (шаг 7, «Откат») и строка `— отказ`; «продолжай» — продолжить: под git — если начало (SHA из строки `— начат`) — предок `HEAD` (`git merge-base --is-ancestor <начало> HEAD`) и коммиты после него трогали только пути закрытого списка, `.claude/` и `wiki/log.md` (иначе — показать человеку, какие ещё пути менялись, и спросить). Продолжение — с первого неотмеченного пункта шага 6 (своя версия — из файла хода, предусловие 1.5 не проверять: `AGENTS.md` и `hooks/` уже наши); клон и разбор — заново (шаги 2–3), старые версии — из `git show <начало>:<путь>` (без git — из `archive/0007/before.tar`). Файла хода нет или в нём нет «да получено» — начать с шага 2.
   - Последняя строка о переходе — `— отказ` моложе 30 дней: не предлагать; вердикт профилактики — «у меня <версия> — в зеркале 3.0.0; переход отложен человеком <дата>». `— отказ навсегда` — не предлагать, пока человек сам не попросит.
   - Иначе — шаг 1.2.

   Незаконченный переход идёт первым в проходе профилактики: её прочие пункты (в том числе автоисправления) — после него.
2. **Git, шелл, зеркало.**
   - Нет git (`git rev-parse` падает) — путь «без git» (шаги 5 и 7).
   - Нет шелла или нет доступа к зеркалу — фраза сути и просьба открыть проект там, где переход пройдёт: в Claude Code — терминал, VS Code или вкладка Code (не проект Claude Desktop); в Codex — с разрешённым доступом в сеть. Строку `не могу` писать, только если человек ответил, что не может или не будет; в таком окружении переход не предлагать 4 недели.
3. **Репозиторий** (`git rev-parse --path-format=absolute --show-toplevel --git-dir --git-common-dir`) — как в шаге 1.3 миграции 0006: проект внутри большего репозитория — сказать и спросить; **общий репозиторий** (авторов-людей больше одного; неглубокий клон считать общим) — переход в отдельной ветке под MR от той ветки, куда в проекте вливают изменения правил; **один автор** в рабочей копии git — не переходить, назвать основную папку; есть `origin` — `git fetch`: на ветке, куда вливают правила, строка 3 `AGENTS.md` уже `3.0.0` — сказать «влей <ветку> в свою», стоп.
4. **Незакоммиченное** — как в шаге 1.4 миграции 0006: идёт слияние или rebase — ждать; автоисправления этого прогона — закоммитить (`lint: автоисправления перед переходом`); незакоммиченные правки человека в путях закрытого списка, `.claude/`, `wiki/log.md` — не коммитить самому: сказать и ждать.
5. **Чужое на месте новых путей.** В корне уже есть:
   - `AGENTS.md` — он не из конструктора (проект с кодом, правила другой программы): **стоп**, сказать человеку и дать выбор — переименовать его (нужное из него потом перенести в правила проекта вопросом), оставить проект на 2.x (`— отказ`) или отложить;
   - папка `hooks/` без `hooks/common.py` конструктора — **стоп** и тот же выбор (куда переложить свою папку);
   - `.codex/` или `.qwen/` — не стоп: их файлы не перезаписываются, новое сливается по записям (шаг 6.4).
6. **Чужие хуки, которые коммитят или пушат**, — как в шаге 1.5 миграции 0006: предложить на время перехода `"disableAllHooks": true` в `.claude/settings.local.json` и продолжить в новом чате; не согласен — переход не начинать. Правило проекта «коммитить или пушить после каждого ответа» до шага 8 не применять — сказать одной строкой.

## Шаг 2. Снимок (вне проекта)

1. **Клон зеркала** — по адресу из шага 2 «Проверки обновлений» своего `methodology/lint.md`; вне проекта, полный:
   ```bash
   D=$(mktemp -d) && git clone -q <адрес зеркала> "$D" && git -C "$D" checkout -q v3.0.0
   ```
   Тега `v3.0.0` нет — человеку: «новый выпуск конструктора ещё не выложен до конца, вернусь к этому на следующей профилактике»; `не могу` не писать, стоп.
2. **Своя версия** — строка 3 `CLAUDE.md` (`> **Версия:** 2.x.y`; при продолжении — из файла хода); `git -C "$D" rev-parse -q --verify "refs/tags/v<моя версия>"` — тега нет: не переходить, сказать прямо («не нашёл в конструкторе версию, с которой начинался проект, — перевести, не задев твои правки, не могу»), строкой в `wiki/log.md`, стоп.
3. **Закрытый список** — файлы `v3.0.0`, которые попадают в скачанный архив:
   ```bash
   git -C "$D" -c core.quotePath=false ls-tree -r --name-only v3.0.0 \
     | while IFS= read -r p; do git -C "$D" check-attr export-ignore -- "$p" | grep -q ': set$' || printf '%s\n' "$p"; done
   ```
4. **Что переименовано и что убрано** — без угадывания переименований:
   ```bash
   git -C "$D" -c core.quotePath=false diff --no-renames --name-status "v<моя версия>" v3.0.0
   ```
   Соответствия — по этой таблице, не по сходству текста:

   | было (2.x) | стало (3.0.0) |
   |---|---|
   | `CLAUDE.md` | `AGENTS.md`; новый `CLAUDE.md` = `@AGENTS.md` |
   | `.claude/hooks/freshness_check.py` | `hooks/start.py` |
   | `.claude/hooks/consent_nudge.py` | `hooks/consent.py` |
   | `.claude/hooks/judge.py` | `hooks/judge.py` |
   | `.claude/hooks/raw_guard.py` (с 2.2.0) | `hooks/raw_guard.py` |
   | — | `hooks/common.py`, `hooks/env_check.py`, `methodology/среда/`, `.codex/`, `.qwen/` |
   | `.claude/knowledge-check.off` | `.knowledge-check.off` или `tmp/knowledge-check/claude/off` (шаг 6.6) |

## Шаг 3. Что твоё (разбор вне проекта)

1. **Файлы закрытого списка, которые есть в проекте** (кроме `AGENTS.md`, `CLAUDE.md`, файлов настроек программ и `hooks/` — пп. 2–4), — три версии во временную папку: мой файл, база `git -C "$D" show "v<моя версия>:<путь>"`, новый `git -C "$D" show "v3.0.0:<путь>"`; затем `git merge-file -p <мой> <база> <новый> > <результат>`. Код 0 — результат готов; конфликт — разобрать по смыслу и вынести в экран «спрашиваю» простыми словами («в обновлении поменялось X, у тебя тут своё Y — оставлю твоё и добавлю X?»). Файл закрытого списка, которого в проекте нет: в теге твоей версии он был — человек удалил: в экран «спрашиваю»; не был — новый, кладётся как есть.
2. **Главный файл** — три версии: мой `CLAUDE.md`, база `v<моя версия>:CLAUDE.md`, новый `v3.0.0:AGENTS.md`; у всех трёх до слияния вырезать раздел «О проекте» и строку 3, после — вернуть «О проекте» дословно и строку 3 прежней (её меняет шаг 8). Конфликтов здесь будет больше обычного: в 3.0.0 из правил убраны названия программ — разбирать так же, по смыслу.
3. **Скрипты.** Четыре старых скрипта канона в `.claude/hooks/` (таблица шага 2.4) — сравнить с `v<моя версия>`: равен — уберётся (шаг 6.5); отличается — правки человека назвать в экране «спрашиваю» (перенести ли и как — по смыслу, в новый скрипт). Свои скрипты человека в `.claude/hooks/` не трогать.
4. **Записи проверок во всех файлах настроек Claude Code** — `.claude/settings.json`, `.claude/settings.local.json`, `~/.claude/settings.json` (только чтение): каждая команда, которая указывает на старый скрипт канона в `.claude/hooks/`, — план замены: путь → `hooks/`, имя скрипта — по таблице шага 2.4, в конец вызова скрипта — `--program claude`; остальную форму команды человека (другой `python`, запись для Windows, свои ключи) не трогать. Команда в точности как в `v<моя версия>` — заменить целиком командой `v3.0.0`, `matcher` `SessionStart` — как в `v3.0.0`. Запись проверки, которой у человека нет, а в его версии она была (удалил сам), — не возвращать; запись `v3.0.0`, которой в его версии не было (страж `raw/` — до 2.2.0), — добавить, кроме отказа в журнале. Строки журнала `настройка | хуки: не ставим`, `настройка | страж raw/: не ставим`, `настройка | стиль: …` — действуют для всех программ: в `.codex/` и `.qwen/` соответствующих записей тоже не ставить (п. 6.4) и сказать об этом в экране.
5. **Выключатель проверки ответов** — есть `.claude/knowledge-check.off`: в `tmp/knowledge-check/log.txt` последние строки до его появления — три `ERR` подряд → выключилась сама после сбоев → `tmp/knowledge-check/claude/off`; иначе это просьба человека → `.knowledge-check.off` в корне. Неясно — спросить в экране.

Итог разбора — во временной папке вне проекта (`$D-razbor.md`).

## Шаг 4. Один экран, одно «да»

Человеку — **одно** сообщение, простыми словами, без слов «версия, тег, слияние, миграция, хук» (и прочих запретных слов своего `lint.md`). Три группы:
1. **Что меняется** — суть и обязательно, по действию:
   - проект будет работать и в Codex, и в Qwen Code; правила — в `AGENTS.md`, рядом `CLAUDE.md` из одной строки — удалять его не нужно;
   - автоматические проверки переезжают в папку `hooks/`;
   - **в Claude Desktop** (если проект открыт там) — строку в инструкциях проекта нужно будет заменить: дам новую;
   - **в Codex и Qwen Code** (если работаешь там) — включить там напоминания, подсказку о записи и защиту исходных документов: подскажу как.
2. **Что у тебя своё и куда переношу** — коротко, по разбору.
3. **Что спрашиваю** — конфликты, удалённые тобой файлы, правленые скрипты, точная замена в личных файлах настроек (впишу я с твоего «да» или ты сам), выключатель.

И вопрос: «переходим? Можно ответить „не сейчас“ или „больше не предлагай“».
- **«Да»** — шаг 5.
- **«Не сейчас» / «нет»** — `переход на 3.0.0 — отказ`, стоп. **«Больше не предлагай»** — `переход на 3.0.0 — отказ навсегда`. В обоих случаях удалить временное вне проекта; хуки выключали на шаге 1.6 — напомнить убрать `disableAllHooks`. Общий репозиторий: строку отказа писать, только если отвечающий решает за правила проекта.

## Шаг 5. Начало (после «да»)

0. **Общий репозиторий** — создать ветку под MR от `HEAD` сейчас; начало = её вершина.
1. Строка журнала `переход на 3.0.0 — начат, начало <SHA HEAD>` (без git — `начало без git`).
2. Файл хода: «да получено <дата>», SHA начала, своя версия, закрытый список, решения человека, пути закрытого списка, **которых в начале нет**.
3. **Под git — статус «до»** в файл хода: `git -c core.quotePath=false status --porcelain -uall --ignored=matching`. Неотслеживаемые и игнорируемые пути закрытого списка, `CLAUDE.md`, `.claude/settings.local.json`, `.claude/hooks/` и `.claude/knowledge-check.off` — копией в `tmp/0007/before/` (откат вернёт их оттуда).
4. **Без git:** копия путей закрытого списка, что есть в проекте, `CLAUDE.md` и всей папки `.claude/` — архивом `archive/0007/before.tar`; опись прочего (путь, размер, mtime) — в `archive/0007/inventory.txt`; есть `archive/index.md` — строка о папке `0007/`.

## Шаг 6. Запись — строго по порядку

Обрыв после любого пункта оставляет проект рабочим: прежние правила и проверки действуют до п. 8, новый `lint.md` с п. 1 вернёт сюда (шаг 0). После каждого пункта — отметка в файле хода.

1. **`methodology/lint.md`** — результат слияния (шаг 3.1).
2. **Прочие файлы закрытого списка** — кроме `AGENTS.md`, `CLAUDE.md`, `hooks/` и файлов настроек программ: результаты слияния; новые (`methodology/среда/` и др.) — как есть. Пути под `wiki/`, `raw/`, `input/`, `output/` (заготовки) — только если такой папки в проекте нет.
3. **`hooks/`** — шесть скриптов из `v3.0.0` байт в байт, `chmod +x`; правки человека из старых скриптов — по его решению.
4. **Файлы настроек программ:**
   - `.claude/settings.json` — по записям, по плану шага 3.4 (свои ключи и записи — байт в байт; запись `outputStyle` — как была);
